# 记忆整理操作清单（FadeMem 落地版）

> 打印出来对着做。适用于任何有"持久记忆 + 容量上限"的 Agent 系统。

---

## 什么时候要整理

- [ ] 记忆占用率 > 80%
- [ ] 写入新记忆时被拒绝（超限）
- [ ] 感觉检索变慢/找不到想要的
- [ ] 距上次整理超过 1 个月
- [ ] 项目阶段切换（旧项目的细节可以沉下去了）

---

## Step 1：盘点（不动手，只看）

### 1.1 导出当前所有记忆

列出每一条，编号。

### 1.2 给每条打权重

| 权重 | 判断标准 | 处置方向 |
|------|---------|---------|
| **3 高频** | 最近一周用过 / 每次会话都可能用到 | 留在热点层 |
| **2 中频** | 最近一个月用过 / 特定场景才用 | 压缩成指针 |
| **1 低频** | 三个月内用过 1-2 次 | 移到档案层 |
| **0 零命中** | 想不起来什么时候用过 | 确认存档后删除 |

**打分技巧**：问自己"下次会话开始时，不看这条会不会出问题？"
- 会出大问题 → 3
- 会多花几分钟查 → 2
- 几乎不影响 → 1
- 完全没影响 → 0

### 1.3 检查档案备份

对每条权重 ≤ 2 的记忆：
- [ ] 档案层有没有对应的完整内容？
- [ ] 如果没有，先写档案，再动记忆
- [ ] **绝对不要先删记忆再补档案**

---

## Step 2：分类处理

### 权重 3（高频）→ 留但精简

```
处理方式：只删冗余措辞，不删信息
例：
  改前：【服务器】IP是192.168.1.100，SSH端口22，用户名admin，可以用密钥登录
  改后：【服务器】192.168.1.100 admin 密钥登录
```

### 权重 2（中频）→ 压缩成指针

```
处理方式：留关键标识 + 指向档案
例：
  改前：【项目X】完整的技术栈、部署流程、注意事项...（500字）
  改后：【项目X】Node22+PG15，详见 项目档案/X.md
```

### 权重 1（低频）→ 全移档案，留一行索引

```
处理方式：整条移到档案文件，记忆里只留一行
例：
  改前：【旧项目Y】...（300字）
  改后：（与其他低频项目合并）【历史项目】X/Y/Z 详见 项目档案/历史.md
```

### 权重 0（零命中）→ 确认后删除

```
处理方式：
1. 确认档案层已有完整备份 ✅
2. 从记忆删除
3. 如果实在不确定，降级到权重1处理（保守做法）
```

---

## Step 3：合并同类项

整理完单条后，看看能不能合并：

- [ ] 同一主题的多条 → 合成一条（如"服务器A""服务器B" → "服务器清单"）
- [ ] 同一类型的指针 → 合成一条（如多个"详见XX.md" → 一条"档案索引"）
- [ ] 相关的规则/流程 → 合成一条（如"路由规则""调用顺序" → "架构路由"）

**合并的底线**：合完之后每条还能一眼看懂在说什么。如果变成大杂烩，说明合过头了。

---

## Step 4：执行

### 4.1 批量操作（如果工具支持）

一次性完成所有增删改，保证原子性。避免删到一半失败导致信息丢失。

### 4.2 统一指针格式

所有压缩后的条目用同样的指针格式：
```
【主题】核心信息。详见 <路径>
```

好处：下次整理时一眼能看出哪些是指针，哪些是完整信息。

### 4.3 档案文件命名规范

```
按主题：  运维/服务器档案.md
按日期：  2026-09-05-XX迁移日志.md
按项目：  项目档案/项目名.md
```

---

## Step 5：验证

- [ ] 占用率降到 **60-70%** 区间（不要压到极限，留缓冲）
- [ ] 高频信息（权重3）**全部还在**
- [ ] 每个指针都能找到对应档案（随机抽查 2-3 个）
- [ ] 没有出现"我记得有个XX，怎么找不到了"的情况
- [ ] 新的记忆整理规则本身也记录下来了

---

## 常见坑

### ❌ 坑1：先删后补
**症状**：删了记忆才发现档案里没有
**预防**：Step 1.3 强制检查，没档案先写档案

### ❌ 坑2：压到极限
**症状**：整理到 95%，一周后又满了
**预防**：目标 60-70%，留 30% 缓冲

### ❌ 坑3：合并过头
**症状**：合成一条巨长的"杂项"，看不懂在说什么
**预防**：每条合并后自问"这条在说一件什么事？"，说不清就拆开

### ❌ 坑4：指针不统一
**症状**：有的写"见XX"，有的写"详见XX.md"，有的没写路径
**预防**：统一格式，一次改完

### ❌ 坑5：只删不加
**症状**：整理完发现丢了重要的踩坑经验
**预防**：整理时同步补充"这次整理学到什么"

## 整理频率建议

| 使用强度 | 建议频率 |
|---------|---------|
| 每天重度使用 | 每 2 周 |
| 每周几次 | 每月 |
| 偶尔使用 | 每季度 |
| 占用率触发 | > 80% 就整理，不看时间 |

---

## 快速版（5分钟应急）

时间紧，只做最关键的三步：

1. **找出明显过期的**（已完成项目、已解决问题）→ 直接删
2. **找出最长的 2-3 条** → 压缩成指针，细节写档案
3. **验证**：占用率降到 70% 以下就收工

剩下的下次再细整理。
